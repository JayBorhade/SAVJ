# Contributing to SAVJ

SAVJ is currently an academic project under active development.

## Principles
- Keep changes focused and reviewable.
- Follow the existing project structure and design system.
- Never commit API keys, tokens, passwords, or private credentials.
- Prefer reusable components over duplicated UI.
- Keep map and external-service integrations modular.
- Validate mandatory task requirements before enabling task acceptance.

## Commit Convention
Use concise conventional-style messages:

- `feat: add task radius filtering`
- `fix: disable acceptance when tools are missing`
- `docs: update architecture`
- `refactor: simplify task card`

## Pull Requests
Before opening a PR:
1. Test the affected flow.
2. Check for build/console errors.
3. Verify no secrets are included.
4. Describe the change and known limitations.
